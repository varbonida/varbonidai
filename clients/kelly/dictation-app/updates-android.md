### 2026-08-20

- Redesigned Home screen colors to match a new brand reference (`home.png`, "Avelisse" palette — warm ivory background, teal accent, terracotta secondary) — layout/typography/spacing/functionality untouched, colors only.
- Centralized the new palette as a "Home palette" section inside the existing `DictusColors.kt` (not a new file) after review feedback; added a `HomeGlassCard` composable alongside the existing `GlassCard` for reuse instead of duplicating card-shape code.

- Fixed a Compose lint warning in `HomeScreen.kt` ("Flow operator functions should not be invoked within composition") by wrapping the DataStore `.map{}` chains in `remember(dataStore) { ... }`.
- Debugged and fixed a native crash: dictation triggered `Fatal signal 4 (SIGILL)` in `libwhisper_v8fp16_va.so` on a Samsung Galaxy A05s (Snapdragon 680, Cortex-A73/A53 cores). Root cause: `WhisperLib.kt` selected the ARMv8.2-A FP16-optimized native library based only on `System.loadLibrary()` succeeding, which doesn't verify the CPU can execute FP16 vector instructions — the device's cores predate ARMv8.2-A. Fixed by gating the fp16/vfpv4 library loads behind an actual `/proc/cpuinfo` feature check (`fphp`/`vfpv4`), matching the pattern already used in upstream whisper.cpp's reference Android sample. Fix is code-only; build/install/on-device verification left to Pierre due to no compatible local JDK for Gradle 8.11.1.
- Redesigned the Models screen to match `models.png` — colors first, then full layout/spacing/cards/badges pass; fixed a bug where the selected model card's shadow and gradient weren't rendering (gradient was a flat semi-transparent color instead of a real `Brush.verticalGradient`; shadow was suppressed by a `graphicsLayer`/`.scale()` on an intervening parent Box — moved `.scale()` onto the same Box that owns the shadow).
- Recolored the bottom navigation bar to match `home.png`.
- Replaced the static app logo/launcher icons with the new wave+particle design from `logo_canvas.html`, rendered as proper Android vector/PNG assets; found and fixed the in-app `DictusWaveformLogo` composable (Home screen) which still had the old shape; extended onboarding to use the same logo.
- Animated the logo (matching `logo_canvas.html`'s JS animation) consistently across the startup loading screen, Home screen, and onboarding — onboarding's static `WaveformBars` swapped for the animated `DictusWaveformLogo`.
- Redesigned the Settings screen to match `settings.png` (layout, colors, spacing, cards, buttons, icons, dividers) without adding/removing any settings.
- Redesigned the Recording screen to match `recording.png` (layout, colors, spacing, buttons, icons, visual hierarchy), preserving all recording/transcription logic and fonts.
- Reshaped the Recording screen waveform from discrete bars into a filled "blob" driven by real mic energy via the existing `WaveformDriver`, matching `recording.png`'s waveform.
- Reworked the waveform's animation/behavior to match a more precise reference (`waveform_canvas.html`): ported its exact envelope/traveling-wave/Gaussian-peak formula into `WaveformBlob`, and extended `WaveformDriver` with a smoothed single-scalar `volume` channel (same fast-rise/slow-decay easing as the bar waveform) so low/medium/high mic volume scales the shape smoothly instead of jumping.

### 2026-08-21

- Investigated a "waveform not displaying" report on the Recording screen: found no logic bug in the shape/color math itself, but a real architectural regression versus the app's own proven-working precedent (`OnboardingTestRecordingScreen.kt`) — the new mic-volume smoothing StateFlow was being collected at the top of the whole `RecordingScreen` composable, forcing a full-screen recompose on every animation frame while recording. Fixed by scoping that collection into two small leaf composables so only the waveform itself redraws per frame.
- When the waveform still wasn't displaying correctly after that fix, simplified per instruction: removed real-time microphone-volume reactivity from the waveform entirely. It's now a pure decorative animation (shape/movement/rhythm ported exactly from `waveform_canvas.html`, fixed amplitude matching the reference's own constant `settings.volume = 0.75`) with no dependency on mic input — `WaveformDriver`'s scalar-volume machinery (added earlier in the week) was removed, restoring that file to its original pre-feature state.
- Rebranded user-facing app name from "Dictus" to "AVELISSE" across app UI, Settings/About, onboarding, notifications, and the launcher/app-info label — package names, class names, technical identifiers, third-party dependency names, and copyright/attribution text (e.g. the Licences screen's "Get Dictus" author/copyright line) were deliberately left unchanged.
- Audited the app for hardcoded/non-localized text (Models screen quality labels and descriptions were hardcoded French strings baked directly into `ModelManager.kt`, plus a hardcoded "Mo" unit label, onboarding's mode picker, the Licences section header, IME accessibility labels, and the notification channel description) and routed all of it through `strings.xml` with English + French translations; also made interface language and transcription language both default to the system language when supported, English otherwise.
- Root-caused the Recording screen waveform rendering as "completely blank" across several fix attempts: a float32 precision bug where `sin(PI.toFloat() * 1.0)` comes out slightly negative (unlike JS's double-precision `Math.PI`), and raising a negative number to a fractional power returns `NaN`, poisoning the entire shape's fill. Found via a step-by-step diagnostic ladder (plain box → Canvas primitive → simple Path → real geometry) rather than more guessing. Restored real-time mic-volume reactivity on top of the fix.
- Redesigned the Recording screen to match `recording.png` more precisely (full-bleed waveform, larger timer/"Recording" label, close icon, Home palette colors) and replaced the transcribing-state bar animation with the animated AVELISSE logo, later widened to scale to the full available width responsively without distorting its proportions.
- Added a short "Dictation Application" tagline under the AVELISSE wordmark on the Home screen.
- Reverted the transcribing-state animated-logo experiment (tried a full-width AVELISSE logo in place of the loading animation) back to the original bars-based loading animation per instruction, cleanly removing the now-unused `width` parameter it had added to `DictusWaveformLogo`.
- Recolored the transcribing-state waveform bars to the AVELISSE Home palette (teal inner bars, muted secondary-text outer bars) instead of the old default blue/white — fixed a real contrast bug where the app's default dark theme made the outer bars render white and nearly invisible against the Recording screen's ivory background.
- Unified the onboarding Test Recording screen with the main Recording screen: extracted the "Recording..." label/timer, the mic-reactive waveform, and the "Transcribing..." indicator into shared composables so both screens now render identically (full-bleed waveform, same colors/sizes/timer), instead of onboarding running its own drifted copy.
- Changed the keyboard's default layout from AZERTY to QWERTY. The real source of the AZERTY default wasn't the scattered fallback reads — it was onboarding step 4 explicitly persisting the pre-selected "ABC" card's layout key on completion, which runs once per install and overrides any other fallback. Updated that default plus every other AZERTY fallback (keyboard rendering, Settings display) consistently; AZERTY/QWERTY remain fully available via the existing Settings picker, and any user who already has a stored preference (either layout) is untouched since onboarding never re-runs.
- Fixed the transcript-logging privacy blocker flagged in the 2026-08-19 audit: dictated text was being written to `dictus.log` in release builds too. The audit's flagged line was one of three — also found `WhisperContext.kt` logging the raw Whisper result and `DictusImeService.kt` logging the full text after committing it to the keyboard. Gated all three behind `BuildConfig.DEBUG` (enabling the `buildConfig` feature on the `ime` and `whisper` modules, which didn't have it yet) so release builds keep a non-sensitive diagnostic line (char/segment counts, timing) but never the actual dictated text; debug builds are unchanged. `FileLoggingTree` and the Settings "Export debug logs" feature were left as-is and still work.
- Flagged an adjacent, out-of-scope finding for later: `KeyboardScreen.kt` logs each manually-typed key label in all builds — that's typed input, not dictated/transcribed speech, so it wasn't touched per the audit's scope.
- Walked Pierre through how to manually verify the transcript-logging fix on-device (dictate the same phrase on debug vs. release, export logs from Settings, confirm it's absent from the release log) — still pending his actual on-device confirmation.
- Migrated the full technical application identity for the AVELISSE rebrand: `dev.pivisolutions.dictus` → `dev.avelissesolutions.avelisse` for the applicationId/namespace across all 5 modules, renamed 8 package directory trees and 11 `Dictus*`-named files via `git mv` (history preserved), and updated the JNI native symbol names in `jni.c` to match — a step that's easy to miss and would have silently broken native transcription at runtime (JNI binds by mangled package name). Also renamed internal literals (`dictus.log` → `avelisse.log`, the DataStore prefs file, `rootProject.name`). Deliberately preserved the "Get Dictus" MIT attribution block on the Licences screen and left README/CONTRIBUTING/PRD/design docs and external GitHub URLs alone — not technical identity, not mine to guess-rename.
- Fixed two post-rename build/run issues Pierre hit: a stale `build/` cache made Hilt see two `@HiltAndroidApp` roots (leftover compiled `DictusApplication.class` from before the rename) — cleared the gitignored build directories; and a stale Android Studio run configuration still pointed at the old Gradle module name `dictus-android.app` after `rootProject.name` changed to `avelisse-android` — pointed Pierre at a Gradle sync + reselecting the module rather than hand-editing `.idea/workspace.xml`.
- Next focus: Pierre to re-sync Gradle, reselect the run config, and do a full install/launch verification on a physical device — since applicationId changed, this is effectively a new app install, not an upgrade over the old `dev.pivisolutions.dictus` build.
